# Spec 0008

Story: none (ribo:tweak fast-path, no story gate)

## Path selection

`docs-only`. This is a documentation copy fix: README.md lists branch-protection
required status-check names that do not match the job names in
`.github/workflows/checks.yml`. No code path, data model, or UI changes.

## What is wrong

`README.md` lines 80-82 tell a maintainer to require these status checks:

```
      typecheck, lint, unit tests, acceptance tests, contract verify.
```

`.github/workflows/checks.yml` defines exactly three jobs, each with a literal
`name:`: `typecheck` (19), `test` (31), `verify` (43). GitHub matches required
status checks by that job `name:`. So four of the five listed names (`lint`,
`unit tests`, `acceptance tests`, `contract verify`) are phantom: a maintainer
who copies README line 81 into branch protection permanently blocks every PR,
because no workflow ever reports a status with those names.

The correct three names already appear, consistent with checks.yml, at
`README.md:110-112`, `.claude/skills/setup/SKILL.md:30`, and
`scripts/setup-bootstrap.ts:383-385` (the real `gh api` call). This spec brings
the one stale line into agreement with those; no other copy is stale (researcher
confirmed docs/tutorial.html, OPERATOR.md, and the explorations HTML do not list
these names).

## The fix

Rewrite `README.md` line 80-81 so the required-check list is exactly the three
real job names, and keep the phantom names out. Use the bare job names GitHub
matches on, with a short parenthetical mapping to what each runs so the maintainer
understands them:

```
- [ ] Require status checks to pass before merging. Require exactly the three
      job names from `.github/workflows/checks.yml`: `typecheck`, `test`
      (runs `npm test`), and `verify` (runs `npm run verify`). GitHub matches a
      required check by its job name, so a name that no job posts blocks every PR.
      (Phase 2 wired these checks; this enforces them at merge time.)
```

Do NOT add an "acceptance tests" required check: `npm test` excludes
`tests/acceptance/**` and no CI job runs `test:acceptance`, so requiring it would
recreate a phantom check.

  it runs in no CI job. Mitigation: called out above and asserted by the test
  (any required name must be a real job name).
