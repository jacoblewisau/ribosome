# Spec 0001

Story: stories/0001.md

## Path selection

`full`. The feature introduces a new DOM contract selector with behavioural invariants; the validator needs the contract harness pass to be authoritative.

## Data model changes

None. UI-only.

## API or background flow

None. UI-only.

## UI changes

Component modified: `src/components/Counter.tsx`.

- Add a new `<button>` element rendered inside the existing `<section data-contract="counter">`, after the existing increment button. The new button:
  - `type="button"`.
  - `data-contract="counter.reset"`.
  - Visible text: `Reset`.
  - `onClick` handler: `() => setValue(initial)`. (Reset to the `initial` prop value, which defaults to 0; not hard zero. Confirmed at gate 1.)
- No new props on Counter; no change to existing props.
- No change to existing `counter`, `counter.label`, `counter.value`, `counter.increment` selectors.

## Tests required

Contract test updates in `src/components/Counter.contract.test.ts`:

- Extend `DOM_CONTRACT` with one entry: `"counter.reset": "the reset button; click returns the value to the `initial` prop"`.
- Add invariants per fixture covering:
  - The `counter.reset` selector is present (already covered by the existing "exposes every DOM contract selector" invariant once added to `DOM_CONTRACT`).
  - Clicking reset on a counter at its initial value is a no-op (value remains at initial).
  - After incrementing some number of times, clicking reset returns the value to `initial`.
  - After reset, the next increment click adds `step` to `initial` (not to whatever the pre-reset value was).
  - Reset is idempotent across multiple clicks (value stays at `initial`).

No new unit test files. No new acceptance test files at this scale; the contract tests are sufficient coverage for every acceptance criterion in the story.

## Risks

- Pattern inconsistency: the existing increment button uses the inline arrow `() => setValue((v) => v + step)`. The reset uses `() => setValue(initial)`. Both are idiomatic React. No risk.
- Contract regression: removing or renaming the new selector after release would break callers. Not a concern at the substrate stage but the convention "do not rename a `data-contract` attribute without updating the contract" already lives in `Counter.tsx:14-15`.
- Accessibility: the new button has no `aria-label`. Same as the existing increment button. Out of scope per the story.

## Open questions

None. The two open questions from the story were resolved at gate 1; the spec encodes the resolutions explicitly (reset target is the `initial` prop value; reset button always visible).
