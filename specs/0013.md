# Spec 0013 (tweak)

Issue: #92 (ribo:tweak, ribo:doc-drift)
Mode: tweak (no story or spec gate; the PR merge is the only gate)

## What this fixes

The coordinator records an auto-advanced spec gate as `gate_state.spec:
"auto-approved"` (ADR-0005, coordinator SKILL.md lines 26, 50, 72). The chain
state helper does not know that value: `GateState` at `src/chain/state.ts:50`
omits it, and `normaliseGateState` (`src/chain/state.ts:94-101`) maps "approved"
via `startsWith("approved")`, which `"auto-approved"` fails (it starts with
`"auto"`), so any read through `readChain` silently rewrites it to `"pending"`.
`npm run chain:show` reads through `readChain` and therefore misreports an
auto-approved chain as `spec=pending`.

The value is deliberately distinct (ADR-0005; `mission-control.ts:98` already
branches on it when parsing the sticky comment marker). So the fix teaches the
type and the normaliser about it, rather than collapsing it onto `approved` or
`phase-skipped`, both of which carry a different meaning in the audit trail.

## Change

Two edits, both in `src/chain/state.ts`, plus the acceptance test.

1. Add `"auto-approved"` to the `GateState` union (line 50):

   `export type GateState = "pending" | "approved" | "auto-approved" | "changes-requested" | "phase-skipped";`

2. In `summarise` (inside `normaliseGateState`), return `"auto-approved"` for
   that value, placed before the `startsWith("approved")` branch so the two stay
   distinct:

   ```ts
   if (lower.startsWith("auto-approved")) return "auto-approved";
   ```

No other file changes. The coordinator SKILL.md is already correct; it is not
edited (and `.claude/**` is off-limits to the builder). `chain-show.ts`
interpolates the gate value into a template literal, so a new union member needs
no change there. No verifier unit reads `state.ts`, so `npm run verify` is
unaffected.

## Tests required

`tests/acceptance/0013.spec.ts`: a vitest test that initialises a chain, uses
`updateChain` to set `gate_state.spec` to `"auto-approved"`, reads it back with
`readChain`, and asserts the value survives as `"auto-approved"` (the regression:
it must not collapse to `"pending"`). Also assert `"approved"` and
`"auto-approved"` remain distinct on a round-trip. Purge the test chain before
and after with `_purgeForTests`, matching `src/chain/state.test.ts`.

## Risks

- Ordering in `summarise`: `"auto-approved"` must be matched before the generic
  `startsWith("approved")` branch. Since `"auto-approved"` does not start with
  `"approved"` this is not strictly required, but the explicit earlier branch
  keeps the intent legible and guards against a future loosening of the
  approved check.
- Exhaustiveness: no `switch` on `GateState` exists that would break on a new
  member (checked: `chain-show.ts` interpolates, `mission-control.ts` compares
  the parsed marker string). Adding the member is safe.
