# Story 0001

## Role, behaviour, outcome

As a user of the Counter component, I want a reset button that returns the value to a known anchor, so that I can start over after exploring without refreshing the page.

## Acceptance criteria

1. The Counter renders a reset button alongside the existing increment button. The reset button is exposed under the `counter.reset` data-contract selector.
2. Clicking the reset button returns the displayed value to the `initial` prop value (defaulting to 0 when `initial` is not provided).
3. Clicking the reset button when the value is already equal to the reset target is a no-op (the value remains at the target; no error).
4. The reset button is visible and enabled at all times, regardless of the current value.
5. The reset button does not modify the `initial`, `step`, or `label` props; it only sets the displayed value.
6. After reset, subsequent clicks on the increment button behave exactly as they did before any clicks (each click adds `step` to the current value).

## Edge cases

- Counter with non-default `initial`, e.g., 5: reset returns to 5, not 0.
- Counter with non-default `step`, e.g., 3: reset does not change `step`; the next increment adds 3.
- Clicking reset multiple times in succession: each click is idempotent against the reset target.

## Out of scope

- Animations or visual transitions on reset.
- Confirmation dialogs before reset.
- A separate "reset to zero" option distinct from "reset to initial".
- Keyboard shortcuts for reset.
- Accessibility improvements (aria-labels, focus management). The increment button does not have an `aria-label` either; that is a separate story.
- Persisting the reset target across sessions.

## Open questions

1. When the reset button is clicked, should the value return to the `initial` prop value, or hard zero? The acceptance criteria above assume the `initial` prop value (the researcher's reading of the prop name). Operator: confirm or set to hard zero in `/changes`.
2. Should the reset button be visible at all times, or hidden when the value already equals the reset target? Above assumes always visible (matches the increment button's behaviour). Operator: confirm.

These two questions are the only points the operator needs to resolve before this story is approvable. If the operator types `/approve`, the assumptions above stand.
