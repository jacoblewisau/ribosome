## Path selection

manifest, no source edits expected. The chain still runs typecheck, the unit
suite, the acceptance test, and the verifier matrix so the operator gets the
same green-checks evidence a full path produces.

## Scope decision: patch group only, majors deferred

Issue #87 lists two groups. This tweak applies ONLY the patch/minor group:

| Package | From | To | Manifest map |
|---|---|---|---|
| react | 19.2.6 | 19.2.7 | dependencies |
| react-dom | 19.2.6 | 19.2.7 | dependencies |
| @types/react | 19.2.15 | 19.2.17 | devDependencies |
| playwright | 1.60.0 | 1.61.1 | devDependencies |

All four stay inside their existing major line (react 19.2.x, playwright 1.x)
and inside their existing caret ranges, so they are non-breaking by semver.

The major group (`@types/node` 25->26, `@vitejs/plugin-react` 4->6, `happy-dom`

scanner's own advice ("merge the patch group first") and the 0006 precedent.

## Dependency change

Four dependencies move to their latest patch/minor within the existing major
line. Apply via a single `npm install` that names all four at their target
versions, so `package.json` and `package-lock.json` update together and
`npm ci` stays consistent:

```
npm install react@19.2.7 react-dom@19.2.7
npm install --save-dev @types/react@19.2.17 playwright@1.61.1
```

(Either one combined install or the two shown; the requirement is that both
manifests move together.) Also tighten the four declared caret ranges to the
new floors, matching the 0006 precedent so the acceptance test's manifest
assertion is meaningful:

- `react`: `^19.0.0` -> `^19.2.7` (dependencies)
- `react-dom`: `^19.0.0` -> `^19.2.7` (dependencies)
- `@types/react`: `^19.0.0` -> `^19.2.17` (devDependencies)
- `playwright`: `^1.60.0` -> `^1.61.1` (devDependencies)

Inspect the resulting `package-lock.json` diff and keep it limited to these four
packages plus any strictly-required transitive updates. No new top-level
dependency is added; `@types/react-dom` is intentionally left untouched (not in
the Issue's patch group).

## Tests required

### Acceptance test

`tests/acceptance/0008.spec.ts`, modelled on `tests/acceptance/0006.spec.ts`.
Read both manifests off disk (not import) and, for each of the four packages,
assert three things so a future lockfile rewrite that reverts any bump fails:

1. `package.json` declares the tightened range in the correct map
   (`dependencies` for react/react-dom, `devDependencies` for
   @types/react/playwright): `^19.2.7`, `^19.2.7`, `^19.2.17`, `^1.61.1`.
2. `package-lock.json` `packages["node_modules/<pkg>"].version` equals the
   resolved target: `19.2.7`, `19.2.7`, `19.2.17`, `1.61.1`.
3. The lockfile root entry range agrees with `package.json`
   (`packages[""].dependencies` / `packages[""].devDependencies`), so the two
   files cannot silently disagree.

Uses the existing vitest harness. No render; just reads the two JSON files
relative to the test file. Runs under `npm run test:acceptance` (the default
`npm test` excludes `tests/acceptance/**`).

## Risks

- **Unexpected transitive churn.** A bump could pull new transitive versions.
  Mitigation: inspect the lockfile diff and keep it to the four packages; the
  verifier matrix and unit suite staying green confirm no behaviour change.
- **Manifest drift.** If only one of the two files moved, `npm ci` would fail.
  Mitigation: the bump goes through `npm install`, which writes both together;
  the acceptance test asserts both files agree for all four packages.
- **playwright minor.** playwright is the only non-patch move (1.60->1.61,
  minor). Its single consumer, `scripts/capture-evidence.ts`, uses the stable
  `chromium.launch` API; typecheck and the suites gate any regression.
