`docs-only` plus a one-line `package.json` alias. This is a documentation and

## What the tweak fixes

`npm run chain:board` runs `scripts/mission-control.ts` with no flags, which
only renders the board to stdout and never touches GitHub. The write path that
updates the pinned `ribo:in-flight` Issue requires `--upsert`, which the
coordinator and shepherd pass by calling `scripts/mission-control.ts --upsert`
directly. Nothing documents this read-only vs write-path distinction, so a
maintainer who runs `chain:board` expecting to refresh the GitHub sticky sees
local output but no GitHub update.

The Issue proposes "and/or": a doc note and/or a `chain:board:update` alias. In
tweak mode the coordinator resolves this scope choice: do BOTH, because each is
low-cost, and the alias mirrors the existing `chain:show` / `chain:list`
two-aliases-over-one-script pattern (package.json lines 17-18). Both together
stay within the tweak budget.

## Changes in detail

1. **package.json** (modify): add one alias immediately after the existing
   `chain:board` line (line 19). No `--experimental-strip-types` drift; copy the
   exact runner prefix of `chain:board` and append ` --upsert`:

   ```
   "chain:board:update": "node --experimental-strip-types scripts/mission-control.ts --upsert",
   ```

   Keep the existing `chain:board` line unchanged (do not add `--upsert` to it;
   its read-only render is intentional and used as the `--dry-run`-free smoke
   render).

2. **README.md** (modify): in the "Inspection commands (maintainer only)" fenced
   block (lines 159-165), add two lines documenting both aliases, matching the
   existing `command   # purpose` shape, and add a one-line note under the block
   explaining the read-only vs write distinction. Accurate wording (per the
   researcher's doc-accuracy check): bare `chain:board` renders whatever chain
   JSON is on stdin and never calls GitHub (so run bare it prints an effectively
   empty board); the write path gathers the live chains and edits the pinned
   Issue. Do NOT imply that bare `chain:board` shows the current live board.

   Suggested block additions (builder may adjust wording, keep it accurate and
   dash-free / emoji-free):

   ```
   npm run chain:board          # render the Mission Control board to stdout (read-only, no GitHub write)
   npm run chain:board:update   # gather live chains and update the pinned ribo:in-flight Issue
   ```

   And a note after the block, for example: "chain:board only renders to stdout;
   it makes no GitHub calls. The write path that refreshes the pinned board is
   chain:board:update (the coordinator and shepherd invoke
   scripts/mission-control.ts --upsert directly)."
