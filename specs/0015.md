# Spec 0015

Story: none (ribo:tweak fast-path, no story gate)
Issue: #109 (dep-scanner proposal, 2026-10-12)

## Path selection

`dep-bump`. This is a routine dependency refresh raised by the dep-scanner
scout. No feature code changes; the only artefact that changes is the lockfile.

## What this tweak does

Refresh `package-lock.json` for exactly the dep-scanner's non-breaking (patch
and minor) packages, which are all already inside the existing caret ranges in
`package.json`. Use a TARGETED update naming only those packages, so nothing
else in the lockfile churns:

```
npm update @testing-library/dom @testing-library/react @types/node @types/react @types/react-dom playwright react react-dom
```

Non-breaking targets (all within the existing `^` ranges, so no major is
crossed and `package.json` does not change):

| Package | From (installed) | Toward | Range in package.json |
|---|---|---|---|
| @testing-library/dom | 10.4.1 | 10.4.x latest | ^10.4.0 |
| @testing-library/react | 16.3.2 | 16.3.x latest | ^16.1.0 |
| @types/node | 25.9.1 | 25.x latest | ^25.9.1 |
| @types/react | 19.2.15 | 19.x latest | ^19.0.0 |
| @types/react-dom | 19.2.3 | 19.x latest | ^19.0.0 |
| playwright | 1.60.0 | 1.x latest | ^1.60.0 |
| react | 19.2.6 | 19.x latest | ^19.0.0 |
| react-dom | 19.2.6 | 19.x latest | ^19.0.0 |

The update is targeted (names the packages) rather than a blanket `npm update`
on purpose: a blanket update would also move vite within `^6.x`, and
`tests/acceptance/0006.spec.ts` pins the lockfile vite entry to exactly `6.4.3`
(a deliberate guard left by chain 0006). Naming the packages leaves vite,
vitest, typescript, happy-dom, pixelmatch, zod, and pngjs untouched, so that
pin stays valid and the diff is limited to the intended packages.

## Explicitly excluded (NOT in this tweak)

The dep-scanner's "major" group requires editing the caret ranges in
`package.json` and reading each changelog. These are breaking-change candidates
and must not go through the ungated tweak fast-path. They are deferred to a
separate, reviewed change:

- @vitejs/plugin-react 4.x -> 6.x
- happy-dom 15.x -> 21.x
- pixelmatch 7.x -> 8.x
- typescript 5.x -> 7.x
- vite 6.x -> 8.x
- vitest 2.x -> 5.x
- zod 3.x -> 4.x

Because the update names only the eight non-breaking packages, none of the above
is touched, including vite's in-range `6.4.4` patch (left out to protect the
chain-0006 pin).

## Tests required

No new test file. The acceptance criterion for a dep-bump is that the existing
gates stay green after the refresh:

- `npm run typecheck` passes.
- `npm test` passes (unit + chain + hook tests).
- `npm run verify` passes (verifier matrix).

The builder should also run `npm run test:acceptance` as a sanity check, since
`npm test` excludes `tests/acceptance/**`. The targeted update leaves vite at
`6.4.3`, so `tests/acceptance/0006.spec.ts` must stay green; if it does not, the
update touched more than intended and the change should stop rather than edit a
committed pin.

## Files to change

- `package-lock.json` (regenerated by the targeted `npm update`; a generated
  artefact).

`package.json` is intentionally NOT edited: every non-breaking target is already
inside its declared range, so the manifest does not change.

## Risks

- regression from a within-range bump: mitigated by running typecheck, the test
  suite, the verifier matrix, and the acceptance suite before the PR is opened.
  The PR is left as a draft for the operator to merge (gate 3).
- churn / pin conflict: avoided by targeting the eight packages by name so vite
  (pinned by chain 0006) and all major-group packages stay put.

## Decisions captured

- **Assumed (inform-only):** this tweak ships only the non-breaking (within
  current major) bumps the scanner identified. The seven major-version bumps are
  left out because they are breaking and deserve changelog review; they are
  deferred, not dropped.
