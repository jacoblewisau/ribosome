# Spec 0003

Story: stories/0003.md

## Path selection

`full`.

## Data model changes

`Todo` (in `src/features/todos/todos.feature.ts`) gains:

- `dueDate?: number` (optional, undefined when not set; otherwise a Unix-milliseconds timestamp).

`TodoFilter` union gains the literal `"overdue"`:

```
export type TodoFilter = "all" | "active" | "done" | "overdue";
```

`addTodo` signature extends to accept an optional `dueDate`:

```
addTodo(state, text, tags = [], dueDate?: number, now: number = Date.now()): TodosState
```

`visibleItems` signature extends to accept `nowMs` because the "overdue" filter is time-dependent:

```
visibleItems(state, nowMs: number): ReadonlyArray<Todo>
```

New pure helpers in `todos.feature.ts`:

```
isOverdue(todo: Todo, nowMs: number): boolean
overdueCount(state: TodosState, nowMs: number): number
parseDueDateInput(input: string): number | undefined
```

`isOverdue` returns `todo.dueDate !== undefined && todo.dueDate < nowMs && !todo.done` (strict less-than per story).
`overdueCount` returns `state.items.filter(t => isOverdue(t, nowMs)).length`.
`parseDueDateInput` accepts an `HTML <input type="date">` value (`YYYY-MM-DD`) and returns the local-noon timestamp; empty string returns `undefined`. Implementation:

```
const m = /^(\d{4})-(\d{2})-(\d{2})$/.exec(input.trim());
if (!m) return undefined;
const [, y, mo, d] = m;
return new Date(Number(y), Number(mo) - 1, Number(d), 12, 0, 0, 0).getTime();
```

`counts` is unchanged (no `nowMs` dependency; overdue is reported separately via `overdueCount`).

## UI changes

### TodoApp

- New optional prop `now?: () => number` with default `() => Date.now()`.
- Resolve `const nowMs = now()` once at render. Pass to `TodoList` and `TodoStats`. Use to compute `overdue` count for the root attribute bag.
- Root `data-verify-overdue-count` attribute (number as string) added.
- Filter controls `filters` array extends to `["all", "active", "done", "overdue"]`.

### TodoForm

- Add a labelled date input `<label htmlFor="todo-due">Due</label>` and `<input id="todo-due" type="date" data-verify-input="todo-due">`.
- On submit, call `parseDueDateInput(dueRaw)` and pass the resulting `number | undefined` as the third argument to `onSubmit` (after text and tags).
- `onSubmit` prop signature changes from `(text: string, tags: string[]) => void` to `(text: string, tags: string[], dueDate: number | undefined) => void`.
- Clear all three inputs after a successful submit.
- New observability attribute: `data-verify-due-input-length`.

### TodoList

- Accept a new prop `nowMs: number` and forward it to every `TodoItem`.

### TodoItem

- Accept a new prop `nowMs: number`.
- Compute `overdue = isOverdue(todo, nowMs)`.
- Root `data-verify-overdue` attribute (`"true"` or `"false"`).
- If `todo.dueDate !== undefined`, render a `<span data-verify-field="due-date">{formatDate(todo.dueDate)}</span>`. `formatDate` returns `YYYY-MM-DD` (`new Date(ts).toISOString().slice(0,10)` is acceptable in this codebase because the parsed dueDate is always local-noon, never crossing the UTC date boundary in either direction in any tz between UTC-12 and UTC+12. Document the choice in a one-line comment).
- The label inside the `<li>` whose `aria-label` is currently `Mark "{text}" as {state}` extends to `Mark "{text}" as {state}. Overdue.` when `overdue` is true.

### TodoStats

- Accept a new prop `overdue: number`.
- Root attribute bag gains `data-verify-overdue` carrying the count.
- Render a fourth span: `<span data-verify-field="overdue">{overdue} overdue</span>` after the active span, separated by ` / `.

### TodoApp wiring

- `TodoApp` computes `overdueCnt = overdueCount(state, nowMs)` and passes to `TodoStats` as `overdue={overdueCnt}` and includes it in the root attribute bag.
- `TodoApp` passes `nowMs` to `TodoList`.
- `TodoApp` passes `nowMs` to `visibleItems(state, nowMs)`.

## Risks

- **Timezone** (first non-trivial application of this category): local-noon parsing is the resolution. The `formatDate` function uses `toISOString().slice(0,10)`, which is UTC. Because local-noon is at minimum 12 hours away from either UTC boundary in any tz from UTC-12 to UTC+12, the formatted date matches the user's intended day. Documented in `TodoItem.tsx` as a one-line comment. If the project ever needs a tz farther than UTC+12 (Kiribati's UTC+14 exists), this resolution breaks; out of scope.
- **Test determinism**: the clock-injection pattern fully resolves this. Existing fixtures that previously used real `Date.now()` are updated to use the fixed clock so they remain deterministic.
- **Filter exhaustiveness**: the `TodoFilter` union gains `"overdue"`. TypeScript's exhaustiveness check on `visibleItems`'s switch will catch the missing case at typecheck time if the switch is well-formed. Builder must add the new arm.
- **Function signature changes**: `addTodo`, `visibleItems`, `onSubmit` of TodoForm. All call sites listed in `Files to change`.
- **Done-dominates-overdue semantic**: explicit in `isOverdue` and tested by the `done-todo-with-past-date-not-overdue` fixture.
- **a11y**: the new date input must be labelled (mandated explicitly above); the overdue suffix in aria-label ensures screen-reader users get the state without colour.
