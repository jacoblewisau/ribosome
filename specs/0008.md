## UI changes

`src/App.tsx` line 19. The single text node inside the existing `<footer>` changes from `Built with Ribosome` to `Crafted with Ribosome`.

Exact rules:
- New text node is exactly `Crafted with Ribosome`: capital `C`, lowercase `w` (matching the existing sentence case), one ASCII space between words, capital `R`. No trailing period, no surrounding whitespace inside the element so `footer.textContent === "Crafted with Ribosome"`.

## Tests required

The footer copy is pinned by an existing acceptance test, `tests/acceptance/0007.spec.ts`, which asserts `footer.textContent === "Built with Ribosome"` (line 32), with the literal also appearing in the `it(...)` title (line 23) and the header comment (line 9). That assertion is the living single source of truth for the footer copy.

This tweak updates those three references in place to the new copy:
- the strict-equality assertion to `expect(footer.textContent).toBe("Crafted with Ribosome")`,
- the `it(...)` title quoting the string,
- the header comment quoting the string,

and adds a one-line note in the file's header crediting chain 0008 for the copy change. No second acceptance test is created: a `tests/acceptance/0008.spec.ts` asserting the identical footer would duplicate 0007's assertion and inflate the diff past the tweak budget for no coverage gain. Updating the existing pin keeps exactly one footer acceptance test and keeps `npm test` green.

- **Casing regression.** Auto-correcting to "Crafted With Ribosome" or lowercasing violates the intended sentence case. The acceptance assertion pins the exact literal `"Crafted with Ribosome"`.

- **Stale assertion left behind.** If `src/App.tsx` changes but the 0007 assertion is not updated, `npm test` fails. Both files are in scope and change together in this one PR.
