- The attribute `data-verify-unit-label="TodoApp"` is preserved exactly. No other attribute is added or removed.
- No surrounding markup changes: the h2 stays as the first child of `<section {...attrs}>` immediately above `<TodoForm>`.

## Risks

- **Identifier confusion.** The substring "Todos" appears in identifiers (`TodosState`, `TodoAppUnit`, `TodosFeatureUnit`, the file name `todos.feature.ts`, the import path `./todos.feature`). The builder must change only the text node inside the h2, not any identifier. Mitigation: the scope-enforce hook does not catch substring renames inside a file; the validator must compare the diff against `Files to change` and reject any non-text-node change to `TodoApp.tsx`. Acceptance criterion 3 in the story is the canonical assertion.
- **Documentation drift with README.** `README.md:111` paraphrases a prior demo as "rename heading to My Todos" (capital T). This run uses lowercase t per the Issue. README is explicitly out of scope (story Out-of-scope bullet 2); a separate `ribo:tweak` can reconcile if the operator wants alignment.
- **Capitalisation regression.** The operator's `/approve` confirmed lowercase t. The builder must not auto-correct to title case ("My Todos"). The acceptance test asserts the exact string `"My todos"`, which catches this. The validator should also flag any title-case rendering as Critical because it violates criterion 1.
