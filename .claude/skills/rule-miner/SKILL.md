You are running the `rule-miner` skill in Ribosome. Phase 4 + 4.5 substrate. Your job is to look at what Ribosome has been learning (from corrections and from the distilled store) and propose rules that should be promoted to CLAUDE.md.

Promotion pipeline (per plan §10):

1. **Distilled memory** (soft, in `.claude/memory/distilled/`). Owned by the `dream` skill.
2. **`MEMORY.md`** at repo root (medium, committed, regenerated by `dream`).
3. **`CLAUDE.md`** (hard, committed). When a distilled item exceeds a reference threshold and survives operator `/keep` confirmation, this skill opens a PR against CLAUDE.md to promote it. Operator merges the PR; the rule is permanent and is removed from distilled.

## Inputs

1. `CLAUDE.md` at the repo root. Read in full; current rules ordered.
2. `.claude/corrections.jsonl`. Each line is a JSON object recording a `/changes <note>` reply or PR review correction. Recent entries are signal; old entries decay.
3. `.claude/memory/distilled/<latest>/store.json`. The current distilled store. Items with high `reference_count` are promotion candidates.
4. `tests/verify/last-run.json`. Frequent failure shapes here are signal of a missing rule.

## When to propose a promotion

A distilled item promotes when ALL of the following are true:

- `reference_count >= 3` (the same lesson has applied across at least three chain runs).
- `confidence >= 0.7` (the dream skill judged it durable).
- The rule it implies is not already covered by an existing CLAUDE.md rule (textual overlap check).
- The operator has not `/forget`-ed it.

Below 3 references, the item belongs in distilled; promoting prematurely bloats CLAUDE.md (rule 5: "100 to 300 lines"). At zero references after several dream passes, the item belongs in `dream`'s decay path.

A correction in `corrections.jsonl` that recurs three times across different chains is also a promotion candidate, even without a corresponding distilled item.

## What to produce

Open a pull request against `CLAUDE.md` only. The PR adds one numbered rule following the convention of rules 11, 12, 13 (each has a footnote citing when it was earned). Template:

```markdown
N. **<one-line rule statement>.**
   <one-paragraph context>. <example or evidence>. Earned
   <YYYY-MM-DD> from <chain id or correction citation>.
```

After the PR merges:

- Remove the distilled item it superseded via `npm run dream:forget <id>`.
- Note in the next dream pass's `source_chains` that promotion occurred.

## What you do not do

- You do not edit any other file in the same PR. CLAUDE.md only.
- You do not propose a rule whose distilled item has `reference_count` below 3. Wait.
- You do not promote a rule the operator explicitly `/forget`-ed in the last two dream cycles.
- You do not re-propose a rule the operator rejected in a previous rule-miner PR. Track rejections in `.claude/corrections.jsonl` (Phase 6 wires the hook; for Phase 4.5 append manually).

## Operator interaction

The operator sees one rule-miner PR per dream cycle (at most). The PR body is two short paragraphs: the rule, and the evidence. The operator clicks Merge to accept, Close with a comment to reject. The reject reason is what `corrections.jsonl` will record.

## Style

No en or em dashes. No emoji. The rule is one sentence. The context is one paragraph. The earned-from footnote is one line.
