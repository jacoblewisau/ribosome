# Story 0006

Issue: #27 (dep-scanner tweak, escalated to the story gate)

## Role, behaviour, outcome

As the maintainer of this repo, I want the project's npm dependencies brought
up to date in a controlled way, so that the toolchain stays current and secure
without the app or the chain changing how it behaves.

## Scope resolved at gate 1

The operator chose **Option A (safe patch only)** by replying `/approve` on
Issue #27 (comment 4610008969). This story therefore covers only the patch
bump: `vite` 6.4.2 to 6.4.3. The six major upgrades listed in Issue #27
(typescript, vitest, happy-dom, zod, vite to 8, and @vitejs/plugin-react) are
explicitly out of scope for this chain and left for a later round.

## Acceptance criteria

1. The patch bump (vite 6.4.2 to 6.4.3) is applied in both `package.json` and
   `package-lock.json`.
2. After the bump, a clean install (`npm ci`) succeeds with no peer-dependency
   errors and no drift between `package.json` and `package-lock.json`.
3. `npm run typecheck` passes.
4. `npm test` passes and the test count does not regress below the current
   baseline.
5. `npm run verify` produces a clean verifier report
   (`tests/verify/last-run.json`).
6. The running app and the chain behave the same to a user after the bump as
   before it: this change is tooling maintenance, not a feature or behaviour
   change.

## Edge cases

- `package.json` and `package-lock.json` fall out of sync, which makes
  `npm ci` fail. Mitigated by running the bump through `npm install`, which
  updates both files together.
- The patch carries an unexpected transitive change. Mitigated by inspecting
  the lockfile diff (it is vite-only) and by the verifier matrix staying green.

## Out of scope

- The six major upgrades from Issue #27 (typescript, vitest, happy-dom, zod,
  vite to 8, @vitejs/plugin-react). Operator chose Option A.
- Adding any new dependency or removing an existing one.
- Changing any app feature, UI, or chain behaviour.
- Refactoring code beyond what the bump forces (which is nothing here).

## Questions and assumptions

- **Resolved (was: Needs you):** How far should the update reach? Operator chose
  Option A, the safe patch only.
- **Assumed (inform-only):** This is pure maintenance; the app and chain behave
  identically afterward. No dependency is added or removed, only vite is moved.
