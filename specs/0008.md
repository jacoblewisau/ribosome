## What to change

The `/keep` and `/forget` rows in the OPERATOR.md command table omit the `<id>`
argument that the coordinator dispatch requires. Verified this session:
`OPERATOR.md` lines 127 to 128 show bare `/keep` and `/forget`, while
`.claude/skills/coordinator/SKILL.md` lines 59 to 60 dispatch on `/keep <id>`
and `/forget <id>` (the id is passed to `npm run dream:forget`). An operator who
types `/forget` with no id has no item removed. The weekly-digest section (lines
130 to 138) also never tells the operator that each entry carries an id.

Three edits, all inside `OPERATOR.md`:

1. Command-table row for `/keep` (currently line 127): change the command cell
   to `` `/keep <id>` `` and extend the description so it names the id, e.g.
   "Used only on the weekly digest Issue. Confirms a memory item the bot wants
   to keep. The `<id>` is the item id shown next to each digest entry."
2. Command-table row for `/forget` (currently line 128): change the command
   cell to `` `/forget <id>` `` and extend the description the same way, e.g.
   "Used only on the weekly digest Issue. Tells the bot to drop a memory item.
   The `<id>` is the item id shown next to each digest entry."
3. Weekly-digest section (currently lines 130 to 138): add one sentence stating
   that each item in the digest shows an id, and that the operator includes that
   id in the reply, for example `/keep <id>` or `/forget <id>`.

Keep the existing table formatting (leading and trailing pipes, one row per
line). Do not renumber, reorder, or touch any other row. Follow the OPERATOR.md
prose conventions: no en or em dashes, no emoji, plain language.
