## Path selection

`dep-bump`. This is a dependency version bump with no source, data-model, or contract change. The gate is that `npm run typecheck`, `npm test`, and `npm run verify` stay green after the bump; no new test is warranted.

## Scope of this tweak: the PATCH group only

The Issue proposes two groups. This tweak covers only the low-risk PATCH group. Every target sits inside the existing caret range in `package.json` (the declared floors were `^19.0.0` / `^25.9.1` / `^1.60.0`), so each is non-breaking by semver intent:

| Package | To | Manifest section |
|---|---|---|

| @types/react | 19.2.17 | devDependencies |
| playwright | 1.61.0 | devDependencies |
| react | 19.2.7 | dependencies |
| react-dom | 19.2.7 | dependencies |

### MAJOR group: deliberately deferred, NOT in this tweak

`@vitejs/plugin-react 4->6`, `happy-dom 15->20`, `typescript 5->6`, `vite 6->8`, `vitest 2->4`, `zod 3->4` are out of scope. Each crosses a major-version boundary with breaking changes the dep-scanner itself flagged ("read changelog before accepting"). They are not tweak-sized: bumping the test runner (vitest), the type checker (typescript), the build tool (vite), the test environment (happy-dom), or the runtime schema library (zod, used on every VerifiableUnit) can change build/test behaviour and likely requires code adaptation. Each warrants its own gated review (a Feature or its own tweak with a changelog read), not the no-gate fast-path. Pushing them ungated to a draft PR for a non-coder operator is precisely what the gates exist to prevent.

## Risks

- **A patch release ships an unexpected regression.** Mitigation: the three green commands plus the acceptance specs are the evidence; the builder must not return with any red check.
- **`playwright 1.61.0` may ship a new bundled chromium build.** `scripts/capture-evidence.ts` launches chromium headless. This is a CI/runtime concern (the browser binary), not a code concern, and is out of scope for the patch diff. A missing-browser CI failure is not a code regression; if the evidence capture step needs the new binary it is installed at CI time, not in this diff.
- **Lockfile churn beyond the five packages.** Mitigation: the builder updates only the five named packages (`npm install <pkg>@<version>` for each, preserving caret style), keeping the lockfile diff scoped to those and their direct resolutions rather than a blanket `npm update`.
