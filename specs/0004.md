# Spec 0004

Story: stories/0004.md

## Path selection

`full`. Introduces a new pure helper, new per-item local state, new keyboard interaction surface, and new contract attributes; warrants both gates and the full chain.

## Data model changes

`Todo` is unchanged. The text field already exists; this story only adds a path to mutate it through the UI.

New pure helper in `src/features/todos/todos.feature.ts`:

```typescript
function setTodoText(state: TodosState, id: TodoId, text: string): TodosState
```

Behaviour:
- Trim the input text.
- If the trimmed text is empty, return the input state unchanged.
- Otherwise return a new state with the matching todo's `text` replaced by the trimmed value. Non-matching items are unchanged by reference.

The helper is pure, returns a new state, no React imports, no side effects beyond returning the new state object. Mirrors the shape of `toggleTodo` (`todos.feature.ts:51-56`).

## UI changes

### TodoItem

The component gains internal state and one new callback prop. Adding the prop is a breaking change to `TodoItemProps`; the only call site is `TodoList.tsx` which is in `scope_paths` per rule 13.

- New prop: `onEditText: (id: TodoId, text: string) => void`. Required. Wired from TodoApp through TodoList.
- New `useState<boolean>(false)` for `isEditing`.
- New `useState<string>("")` for `draft` (the in-progress text being edited).
- Root `verifyAttrs` call gains `editing: isEditing`. The data-verify attribute name is `data-verify-editing`, value `"true"` or `"false"`.
- The existing `<span data-verify-field="text">{todo.text}</span>` becomes a conditional render:
  - When NOT editing: render the span as today, but add `tabIndex={0}` and an `onClick={enterEditMode}` handler. The element is now focusable.
  - When editing: render a labelled `<input type="text">` pre-filled with `draft`. The input has `data-verify-input="edit-text"`, `aria-label={\`Edit text for "{originalText}"\`}`. The label is implicit via aria-label (no visible `<label>` element to avoid layout shift; the a11y verifier accepts aria-label as the labelling mechanism).

### Keyboard and focus

While the edit input is focused:

- `onKeyDown` handler. Keys handled:
  - `Enter`: if `draft.trim()` is non-empty, call `onEditText(todo.id, draft)`, then set `isEditing=false`. If empty, set `isEditing=false` without calling `onEditText`.
  - `Escape`: set `isEditing=false` without calling `onEditText`.
  - Other keys: default behaviour.
- `onBlur` handler: set `isEditing=false` without calling `onEditText`. This implements click-outside cancel (criterion 6).

When entering edit mode:

- Set `draft = todo.text` (the current value, not trimmed; if the stored text has leading or trailing whitespace, the user sees it and can preserve it).
- Set `isEditing=true`.
- The input element receives focus immediately via a `useEffect` that fires when `isEditing` flips to `true`. Use a `ref` for the focus call.

When exiting edit mode (save or cancel):

- Set `isEditing=false`.
- Focus the text span (which is now rendered again). Use a second `ref` for this.

### TodoApp

Adds `onEditText` handler:

```typescript
const onEditText = (id: TodoId, text: string) => setState((s) => setTodoText(s, id, text));
```

Passes through to `TodoList`.

### TodoList

Accepts `onEditText` prop. Passes through to each `TodoItem`. Type addition only; no logic change.

### TodoForm, TodoStats, FilterControls

Unchanged.

## Risks

- **Accessibility (focus management)**: the load-bearing risk. The spec mandates explicit focus on the input on edit-start and on the text span on edit-end. The a11y verifier catches the labelled-input miss (covered by `aria-label` on the input); it does not catch missing focus transfer. The builder must use refs and useEffect correctly. The validator should compare the spec's focus-management text against the implementation; if focus management is silently skipped, the validator reports it as Important under accessibility.
- **Prop signature change**: `TodoItemProps` gains a required `onEditText`. Every importer is in scope per rule 13; the spec lists all of them.
- **Concurrent edits**: criterion 8 mandates independence; the per-item `useState<boolean>(false)` gives this naturally because each instance has its own state.
