# Spec 0008

Story: none (ribo:tweak fast-path, Issue #102). Dependency bump proposed by the dep-scanner scout.

## Path selection

`dep-bump`. This is a lockfile-level bump of seven existing dependencies to newer
patch/minor-within-major versions. No source code changes, no new behaviour, no
new package. Verification is the existing gate suite, not a bespoke acceptance
test.

## Scope of this tweak

The PATCH group only (the dep-scanner's lowest-risk group; it recommended
merging patch first):

| Package | From | To | Kind |
|---|---|---|---|
| @testing-library/react | 16.3.2 | 16.3.3 | dev |
| @types/node | 25.9.1 | 25.9.5 | dev |
| @types/react | 19.2.15 | 19.2.18 | dev |
| @types/react-dom | 19.2.3 | 19.2.7 | dev |
| playwright | 1.60.0 | 1.63.0 | dev |
| react | 19.2.6 | 19.2.8 | dependency |
| react-dom | 19.2.6 | 19.2.8 | dependency |

All seven targets sit inside the existing caret ranges in `package.json`
(confirmed by the researcher), so `npm update` moves them and regenerates
`package-lock.json` (lockfileVersion 3) without any `package.json` range edit.

The MAJOR group is explicitly OUT OF SCOPE: @vitejs/plugin-react 4->6,
happy-dom 15->20, typescript 5->7, vite 6->8, vitest 2->5, zod 3->4. Those are
breaking, require reading each changelog, and would almost certainly break the
build; they are not tweak-sized. The weekly dep-scanner will re-surface them.

## How the builder performs the bump

Run exactly:

```
npm update @testing-library/react @types/node @types/react @types/react-dom playwright react react-dom
```

`npm update` respects the caret ranges and moves the lockfile to the latest
in-range versions (the targets above). Do NOT edit `package.json` versions by
hand and do NOT run a bare `npm install <pkg>@latest` (that could pull a major).
If `npm update` also refreshes unrelated in-range transitive entries in the
lockfile, that is expected and fine.

If the registry is unreachable and the bump cannot be produced, stop and report
it plainly; do not fake the lockfile.

## Files to change

- `package-lock.json` (regenerated by `npm update`; the substantive change).
- `package.json` (only if a range genuinely changes, which is not expected here).

## scope_paths

`["package.json", "package-lock.json"]`

## Tests required

No new test. The acceptance criterion for a dep bump is that the existing gate
suite still passes with the bumped versions. The builder must run and report:

- `npm run typecheck` passes (covers src + tests, including playwright-typed
  acceptance specs).
- `npm test` passes.
- `npm run verify` passes (the matrix exercises @testing-library/react `render`
  under happy-dom, pulling react + react-dom 19.2.8).

Do NOT add `tests/acceptance/0008.spec.ts`; there is no new behaviour to assert
and a version-pinning test would be brittle. The three gate commands are the
verification.

## Risks

- Playwright types (low): `npm run typecheck` compiles the playwright-typed
  acceptance specs; a 1.60 -> 1.63 minor bump could shift an exported type.
  Mitigation: the typecheck gate catches it; if it breaks, report, do not patch
  unrelated files.
- react / react-dom / testing-library render (low): `npm run verify` executes
  `render`/`fireEvent`; a patch React change is very unlikely to alter output.
  Mitigation: the verify gate catches it.
- `skipLibCheck: true` limits @types breakage.
